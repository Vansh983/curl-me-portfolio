**Verdict: build responsive WASD keycaps first, then optional quiet audio. Skip haptics for the laptop version.** A webpage cannot add a programmable buzz to an ordinary MacBook or Windows laptop’s keyboard or trackpad. MacBook clicks can retain their normal system haptic feel, but pressing W cannot trigger that motor through a web API. **1. What haptics actually work**

- **Desktop `navigator.vibrate()`:** Chrome and Edge expose it, but their desktop implementation produces no vibration. Safari does not implement it. Firefox removed support in version 129. A supported API or `true` return value does not establish that anything physically vibrated. [Can I use](https://caniuse.com/vibration), [Chromium source](https://raw.githubusercontent.com/chromium/chromium/main/services/device/vibration/vibration_manager_impl.cc), [MDN](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/vibrate)
- **Phones:** Android Chrome and Samsung Internet support vibration on suitable hardware, after user interaction, subject to device settings. Current Firefox Android does not. iPhone Safari and other WebKit browsers do not expose it. [MDN](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/vibrate), [W3C implementation report](https://w3c.github.io/vibration/reports/implementation.html)
- **MacBook Force Touch:** Safari can observe pressure and force-click events, whose physical gesture receives system feedback. It cannot request arbitrary trackpad pulses for movement, footsteps or doors. Programmable trackpad feedback belongs to native AppKit’s `NSHapticFeedbackManager`. [Safari events](https://developer.apple.com/library/archive/documentation/AppleApplications/Conceptual/SafariJSProgTopics/RespondingtoForceTouchEventsfromJavaScript.html), [AppKit](https://developer.apple.com/documentation/appkit/nshapticfeedbackmanager)
- **Controllers:** `gamepad.vibrationActuator.playEffect("dual-rumble", …)` controls duration and strong/weak vibration magnitudes. Current Chromium and macOS Safari support this path, depending on controller and connection. Firefox has the older `hapticActuators`/`pulse()` path, not `playEffect`; iOS Safari support remains absent. [MDN API](https://developer.mozilla.org/en-US/docs/Web/API/GamepadHapticActuator/playEffect), [compatibility data](https://raw.githubusercontent.com/mdn/browser-compat-data/main/api/GamepadHapticActuator.json), [WebKit iOS issue](https://bugs.webkit.org/show_bug.cgi?id=263022)
- **Trigger rumble:** Chromium 126 added `"trigger-rumble"` for compatible controller trigger motors. Check `actuator.effects`, handle rejection, and never infer support from a connected controller alone. This is vibration, not programmable trigger resistance. [Chrome notes](https://developer.chrome.com/blog/new-in-chrome-126), [Gamepad specification](https://www.w3.org/TR/gamepad/#dom-gamepadhapticeffecttype-trigger-rumble)
- **iPhone switch trick:** Safari introduced `<input type="checkbox" switch>` in 17.4. Workarounds route a genuine tap through a hidden switch’s label to obtain native toggle feedback. This is a fragile tap workaround, not arbitrary vibration or held-key feedback. **Not worth using here.** [WebKit](https://webkit.org/blog/15054/an-html-switch-control/), [implementation](https://github.com/tijnjh/ios-haptics)
- **Other real routes:** WebHID can address supported external peripherals with permission; ordinary keyboard/mouse collections are protected. It offers no general laptop-trackpad solution. [Chrome WebHID documentation](https://developer.chrome.com/docs/capabilities/hid)

**2. Six useful examples of “feel” without laptop haptics**

- **[Monkeytype](https://github.com/monkeytypegame/monkeytype/releases):** reactive on-screen keymap. Closest reference for immediate input acknowledgement.
- **[Bruno Simon’s 2019 portfolio](https://github.com/brunosimon/folio-2019/blob/master/src/javascript/World/Sounds.js):** engine pitch and volume follow speed and acceleration. Feedback follows movement.
- **[Patatap](https://patatap.com/):** input produces synchronized sound and animated shapes.
- **[Chrome Dino](https://chromium.googlesource.com/chromium/src/+/refs/tags/98.0.4758.55/components/neterror/resources/offline.js):** immediate jump animation, with separate jump, collision and score sounds.
- **Quake III:** [movement-driven camera bob and landing kick](https://github.com/id-Software/Quake-III-Arena/blob/master/code/cgame/cg_view.c), plus [surface-specific footsteps](https://github.com/id-Software/Quake-III-Arena/blob/master/code/cgame/cg_event.c).
- **[Halo Infinite](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/117):** adjustable shake, radial blur and speed lines. Useful precedent for making these effects optional.

**3. How to build the HUD well**

These are proposed design choices, not universal timing standards.

- **Layout:** fixed bottom left, paper-and-ink styling. W above A/S/D; wider Shift beside them; compact E, Esc and mouse glyph alongside. Use real HTML buttons with text legends, plus an SVG mouse. Suggested targets: 44px, with 16–24px edge spacing.
- **Press feel:** move the key face down about 2px over 40–60ms; reduce its apparent depth and change fill. Stay depressed throughout the hold; release over 80–120ms. No repeating bounce. Animate `transform`/`opacity`, keeping dimensions fixed. [Animation guidance](https://web.dev/articles/animations-guide)
- **Shared input:** pointer down starts the same movement action as keyboard down. Capture the pointer; release on `pointerup`, `pointercancel` and `lostpointercapture`. Track keyboard and each pointer separately so releasing one source cannot cancel another. No synthetic keyboard events. [Pointer capture](https://developer.mozilla.org/en-US/docs/Web/API/Element/setPointerCapture)
- **Pointer-lock constraint:** keycaps are clickable with the cursor unlocked. While looking under pointer lock, mouse events target the canvas, so keycaps act as keyboard indicators. Preserve click-to-look and Esc-to-leave. [Pointer Lock API](https://developer.mozilla.org/en-US/docs/Web/API/Pointer_Lock_API)
- **Keyboard:** react to state transitions, not autorepeat. Clear both movement and HUD on blur, hidden page, Command, pointer-lock changes and mode exit. Preserve the existing editable-field and modifier guards. Focused HUD buttons must handle Enter/Space without also triggering the global interaction handler. [Existing handlers](/Users/vsood/work/curl-me-portfolio/src/scripts/stage-run.ts:2244)
- **Layouts:** retain `event.code` for physical movement positions: WASD becomes ZQSD on AZERTY. Use `event.key` for observed labels; optionally use `getLayoutMap()` where available, with a fallback. [MDN keyboard codes](https://developer.mozilla.org/en-US/docs/Web/API/KeyboardEvent/code), [layout-map limitations](https://developer.mozilla.org/en-US/docs/Web/API/Keyboard/getLayoutMap)
- **Accessibility:** accessible action names, visible focus, keyboard activation and no per-press live announcements. Momentary movement buttons should not use `aria-pressed`, which denotes a toggle. Reduced motion should retain immediate state changes without animated travel. [ARIA](https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/Reference/Attributes/aria-pressed), [reduced motion](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-reduced-motion)
- **Performance:** cache button references and update classes only on input changes. No geometry reads or HUD polling inside `tick()`. Walk already caches geometry through `roamLayout` and `measureRoam()`. [Runtime cache](/Users/vsood/work/curl-me-portfolio/src/scripts/stage-run.ts:1501), [measurement](/Users/vsood/work/curl-me-portfolio/src/scripts/stage-run.ts:2208)

If controller controls are added later, consider brief, optional `dual-rumble` on successful interactions, only for an active supported controller.
